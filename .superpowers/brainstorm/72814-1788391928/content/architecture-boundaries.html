Tres formas de usar Bill-LM, un solo contrato de análisis

La diferencia está en quién ejecuta el modelo y dónde vive la infraestructura; las reglas, el formato del resultado y las validaciones deben ser compartidos.

1

Cloud · BYOK

Navegador → web actual → cola/worker → credencial cifrada del usuario → OpenAI o Claude. Sin whitelist; el backend valida ownership y una conexión utilizable.

2

Local · Suscripción/OAuth

Codex, Claude Code u OpenCode autenticado → skill del proyecto → MCP Bill-LM → workspace local. El host usa la suscripción; Bill-LM nunca copia ni almacena el token OAuth.

3

Local · GPU propia

Runner Bill-LM → endpoint local compatible → modelo cargado → SQLite/JSONL → visor localhost. No requiere Clerk, Firebase, MinIO, Redis ni una CLI de agente.
